## 1. 一句话定义

**块缩放浮点格式（Block Floating-Point, BFP）** 是把一个张量切成若干**连续小块**，每块**共享一个缩放因子（scale）** 把本块峰值映射到低位宽浮点的可表示上界、块内每个元素仍用低 bit 浮点（FP8/FP4）编码的一族数据格式——核心思想是**把缩放粒度从"每张量一个 scale"细化到"每小块一个 scale"**，从而在更低 bit 下既保住动态范围又保住精度。代表是 OCP **MX** 族（MXFP8 / MXFP4）、NVIDIA **NVFP4**、华为 **HiF4**，2023–2026 年随 Blackwell / Ascend 硬件原生支持而成为低精度训练与推理的主战场。

> [!note] 三个关键词别混
> - **BFP（Block Floating-Point）**：一族格式的总称，凡是"块共享 scale + 块内低 bit 浮点"的都算。
> - **MX（Microscaling Formats）**：OCP 开放标准里的 BFP 子族，规定 block size = 32、scale 用 8 位。MXFP8 / MXFP4 都属 MX。
> - **per-block scaling**：一种**缩放策略**（粒度），BFP 格式天然就是 per-block，但 per-block 也能不绑定具体格式（见 [[FP8量化方案]] §3.2）。

## 2. 为什么需要它（动机与背景）

### 2.1 per-tensor 缩放的死穴：离群点主导

传统低精度（FP8 per-tensor）用**整个张量一个 scale** $s = \text{max\_representable} / \max|x|$。问题是 LLM 张量里常有**少数离群点（outlier）**——比如 attention 某行、激活某通道的量级远大于其余。离群点把全局 $\max|x|$ 拉得很大，于是 $s$ 很大，**其余正常值** $|x_i| \ll \max|x|$ 被 $s$ 压进低位宽浮点的窄精度区甚至最小台阶以下，**直接被截成 0，相对误差 100%**。

数学上（详见 [[FP8量化方案]] §4.2）：设张量 $X$ 最大元素为 $M$，per-tensor scale $s = 448/M$（E4M3），小元素 $x_i \ll M$ 量化后 $x_i/s = |x_i| M/448 \ll 448$，落入 FP8 最小台阶以下 → 截 0。

### 2.2 块缩放的破局：局部归一

BFP 把张量切成连续小块，**每块自己挑一个 scale** 把本块峰值映射到格式上界。离群点只影响它所在那一块（那块 scale 大、把离群点服务好），其余正常块 scale 小、用自己的满精度表示正常值 → 整体精度回升。**粒度越细（块越小）越准**，但每块要存一个 scale 元数据 → **块越小元数据越多越费显存/算力**。这就是所有 BFP 格式设计的核心取舍轴：

$$\text{精度} \uparrow \text{ 当 } K \downarrow，\quad \text{但元数据开销} \uparrow \text{ 当 } K \downarrow$$

$K$ = block size（每 scale 管几个元素）。各家格式（MXFP8/MXFP4/NVFP4/HiF4）本质都是在 $K$、scale 类型、元素编码上做不同权衡。

### 2.3 为什么不直接用更宽的浮点（BF16）了事

LLM 规模与上下文暴涨，BF16 也吃不住——显存墙、带宽墙、算力墙。4-bit BFP 相比 BF16 显存省 ~3.5×、吞吐再翻倍；8-bit BFP（MXFP8）相比 BF16 省 2×、且 block scaling 让精度几乎无感（B200 实测 LPIPS 损失仅 ~0.11）。但 per-tensor 低 bit 精度塌（2.1 的离群点问题），必须靠块缩放把精度救回来。BFP 是"既要低 bit、又要精度"的折中产物。

## 3. 核心概念详解

### 3.1 BFP 的三段式通用结构

任何 BFP 格式都由三部分组成：

$$\underbrace{\text{scale}}_{\text{共享缩放因子}} \times \underbrace{\text{micro-scale (可选)}}_{\text{层级细化}} \times \underbrace{\text{element}}_{\text{低 bit 浮点编码}}$$

1. **scale（缩放因子）**：一个块共享 1 个（MXFP8/MXFP4）或一组层级（HiF4 三级）。类型可以是纯指数（E8M0）、无符号浮点（E6M2）、FP8 浮点（E4M3）等。决定**组间 + 组内动态范围**。
2. **micro-scale（微缩放，可选）**：在 scale 之下再加一层或几层细化的指数（1-bit 微指数），用于进一步展开组内局部动态范围、抑制离群点。HiF4 的 E1_8 / E1_16 就是。
3. **element（元素编码）**：块内每个值用低 bit 浮点表示，常用符号-尾数（S1P2）或指数-尾数（E2M1 / E1M2）。决定**精度（有效数字）**。

> [!note] SXPY 记法 vs EXMY 记法
> - **SXPY**：S=符号位，P=二进制小数点，X=整数部分位数，Y=小数部分位数。`S1P2` = 1 符号 + 1 整数 + 2 小数 = 4 bit，表示 $\pm\{0, 0.25, 0.5, ..., 1.75\}$。
> - **EXMY**：E=指数位，M=尾数位（规格化前隐含 1.）。`E2M1` = 2 指数 + 1 尾数（+1 隐含）= 4 bit。
> - `S1P2` 概念上等价于 `E1M2`（1 指数 + 2 尾数，隐含 1 → $\pm\{0.25..1.75\}\times2^e$）。HiF4 论文用 SXPY 记法因更直观，NVIDIA NVFP4 用 EXMY。下文沿用各自原始记法。

### 3.2 OCP MX 族总览（block size = 32）

Open Compute Project 的 **Microscaling Formats (MX) v1.3** 规范（arXiv:2310.10537，微软/Meta 推动，源自"共享微指数"思想）定义一族"小块共享 scale"的低比特格式，**统一规定 block size $K=32$、scale 用 8 位**：

| MX 成员 | 元素位宽 | 元素编码 | scale 类型 | 平均存储 | 用途 |
|---|---|---|---|---|---|
| **MXFP8** | 8 | E4M3 / E5M2 | E8M0（8 位无符号指数） | ~8.25 bit/value | 训练+推理，训推统一希望 |
| **MXFP6** | 6 | E2M3 / E3M2 | E8M0 | ~6.25 bit/value | 中间精度实验 |
| **MXFP4** | 4 | S1P2(E1M2) 或 E2M1 | E8M0 或共享 8-bit 指数 | 4.25 bit/value | 4-bit 量化（精度差，多 weight-only） |
| **MXINT8** | 8 | INT8 | E8M0 | ~8.25 bit/value | 整数 BFP |

**E8M0 scale**：8 位**全是无符号指数**、无尾数，即纯 2 的幂次 $2^e$。一个 MXFP8 元素的真实值 $= \text{scale}_{E8M0}\times\text{FP8\_element}$，32 个元素共用一个 $2^e$ 乘数。E8M0 选纯指数是为硬件实现极简（只是一个移位），但精度粗（只能 2 的幂次跳）——这是 MX 族"省硬件但 scale 粗"的权衡。

### 3.3 MXFP8 详解（8-bit 块缩放，主流甜点）

- **结构**：每 **32 个连续 FP8 元素共享一个 E8M0 scale**。元素仍是 §[[数值类型与精度]] 8.2 的 E4M3 / E5M2。
- **表示**：$x = \text{scale}\_{E8M0}\times\text{FP8\_element}$。
- **对比普通 per-tensor FP8**：粒度从 1（整张量）细到 32（每 32 元素），量化误差显著下降。代价：多存每 32 元素 1 字节 scale（$\approx 0.25$ bit/value 开销）。
- **硬件支持**：**NVIDIA Blackwell（SM 10.0+，B100/B200）原生 Tensor Core 加速**；AMD MI350X、华为 Ascend 亦支持。
- **应用**：训练（前向 E4M3、反向 E5M2，配方见 arXiv:2506.08027《Recipes for Pre-training LLMs with MXFP8》）+ 推理。B200 上 Flux.1-dev 扩散推理加速 1.21–1.26×、显存大幅下降、LPIPS 损失 ~0.11（几乎无感）。
- **地位**：MXFP8 是 2025–2026 训推统一的"甜点"——同一 OCP 规范、同一位布局、同一缩放粒度，训推都用它即可消除"方案不一致"这层 [[训推不一致]]。截至 2026 仍在推广期（TE/vLLM 默认仍各用老方案，详见 [[FP8量化方案]] §8.1）。
- **工程入口**：NVIDIA Transformer Engine 2.18+、PyTorch torchao `MXDynamicActivationMXWeightConfig`、cuDNN 的 MXFP8 SDPA。

### 3.4 4-bit 三巨头：MXFP4 / NVFP4 / HiF4（2025–2026 前沿）

把位宽再砍到 4-bit，吞吐/显存再翻倍，但精度更难保——4-bit 只有 16 个台阶，per-tensor 几乎不可用，必须靠更精细的块缩放。于是各家在"块大小 $K$ + scale 类型 + 元素编码"上分化出三条技术路线。三者都属 BFP，平均存储都在 ~4.5 bit/value 量级，但设计哲学不同。本节先给总览，§3.5–3.7 分别深挖。

| 维度 | MXFP4（OCP 标准） | NVFP4（NVIDIA 专有） | HiF4（华为，arXiv:2602.11287） |
|---|---|---|---|
| 4-bit 元素编码 | S1P2（=E1M2）→ 后改 E2M1 | **E2M1**（2 指数+1 尾数，2 位有效数字） | **S1P2（=E1M2，3 位有效数字）** |
| 组大小 $K$（每 scale 管几个元素） | 32 | **16** | **64** |
| 缩放因子类型 | 共享 8-bit 指数（E8M0） | **FP8-E4M3 浮点 scale**（细粒度但硬件贵） | **三级层级**（E6M2 + E1_8 + E1_16） |
| 平均存储 | 4.25 bit/value | 4.5 bit/value | 4.5 bit/value |
| 全局动态范围 | 窄 | 22 binades（[-10,11]） | **69 binades（[-50,18]）** |
| 组内动态范围 | 3.58 binades | 3.58 binades | **4.81 binades** |
| 是否需软件 PTS | 否 | **是**（E4M3 scale 范围不够，靠 per-tensor scale 补） | **否** |
| 主要用途 | weight-only（激活一上就崩） | 权重+激活、推理/训练（GPT-OSS 等用 weight-only） | 权重+激活，推理+预训练+RL |
| 硬件 | Blackwell / AMD / 华为 | **Blackwell Tensor Core 专有加速** | Ascend NPU 原生（CUDA 侧有模拟库） |
| 量化误差（MSE 相对值） | 1.89 | 1.32 | **1.0（最低）** |

> [!tip] 怎么记这三家
> - **MXFP4**：最"省"（4.25 bit、E8M0 纯指数 scale 硬件最简）但最"糙"（精度差、只能 weight-only）。
> - **NVFP4**：用 FP8-E4M3 浮点 scale 把 E2M1 的表达空间榨干，精度中等、吞吐最高，但 scale 范围不够要软件 PTS 救场、且硬件面积大。
> - **HiF4**：用**大组 64 + 三级层级微指数**，把元数据压到 0.5 bit/value 的同时覆盖最宽动态范围，精度最高、硬件面积最小，是当前 SOTA。

### 3.5 MXFP4：共享微指数的折中失败

- **结构**：$K=32$，每 32 元素共享一个 8-bit 指数 scale，元素 E2M1（牺牲 S1P2 的 1 位有效数字，换成 2-bit 微指数扩大组内动态范围到 3.58 binades）。
- **为什么精度差**：E2M1 只有 2 位有效数字（4 个台阶/数），太稀疏；且 32 元素共享一个 scale，组内动态范围仍受限。实测对**权重+激活同时量化**精度严重退化。
- **现状**：目前多用于 **weight-only**（如 OpenAI GPT-OSS），把 4-bit 算力浪费了——只省显存不省算力。
- **历史教训（MX4）**：更早的微软/Meta **MX4** 用 $K=16$ + 8-way 1-bit 微指数，元数据开销 1 bit/value 太重，被迫把组内降到 3 bit 反而比 vanilla 4-bit BFP 还差，被 AMD Versal 弃用（只留 MX6/MX9）。说明**块太小元数据反噬**——HiF4 选 $K=64$ 正是吸取此教训。

### 3.6 NVFP4：浮点 scale 的精度榨取

- **结构**：$K=16$，每 16 元素共享一个 **FP8-E4M3 浮点 scale**（不是纯指数！），元素 **E2M1**。
- **两点改进 over MXFP4**：
  1. **浮点 scale**：纯 2 的幂次 scale（power-of-two）不能保证把每块峰值归一到 E2M1 上界（浪费表达空间），NVFP4 换成 FP8-E4M3 浮点 scale，细粒度填满 E2M1 的表达空间。
  2. **小 $K=16$**：组更小，离群点影响更局部，降低 outlier 驱动的量化误差。
- **两个代价**：
  1. **动态范围不够，需 PTS**：E4M3 scale 本身范围只 22 binades，对跨张量的大动态范围不够，推理/训练都需额外**软件 per-tensor scaling（PTS）**先做一次粗归一再量化。PTS 是额外算子，性能损失。
  2. **硬件面积大**：浮点 scale 配小 $K=16$，在 64 长度点积里要 4 对 NVFP4 单元、4 个小浮点乘法器 + 4 个大整数乘法器 + 浮点累加树，面积/功耗开销显著。
- **地位**：Blackwell 原生加速，吞吐最高、显存最小（比 BF16 小 ~3.5×），适合高 batch compute-bound 场景；但精度受限，多数实部署仍 weight-only 或配 PTS。

### 3.7 HiF4（HiFloat4）：三级层级缩放的 SOTA

华为 2026-02 提出（arXiv:2602.11287，作者含华为海思），是当前 4-bit BFP 精度与硬件效率的 SOTA。

**结构**：一个 HiF4 单元 = **64 个 4-bit 元素 + 32 bit 共享 scaling 元数据**，平均 **4.5 bit/value**。元数据是**三级树形缩放层级**：

```
64 个元素
 ├─ Level 1: 1×E6M2   (8 bit, 全局基础 scale, 管组间动态范围)
 ├─ Level 2: 8×E1_8    (8 bit, 8 个 1-bit 微指数, 每管 8 元素)
 └─ Level 3:16×E1_16   (16 bit,16 个 1-bit 微指数,每管 4 元素)
                                              └─ 64×S1P2 (4-bit 元素)
```

- **Level 1 `E6M2`**：8-bit 无符号浮点（6 位指数 bias 48 + 2 位尾数 + 1 位隐含整数）。**全局基础 scale**，负责**组间**动态范围（跨 64 元素组），把每组峰值归一到组内结构上界。最大值 $2^{15}\times1.50$，最小 $2^{-48}$，全局范围 [-50,18] = 69 binades。
- **Level 2 `E1_8`**：8 个 1-bit 微指数，每组 8 元素一个。直接编码 $\{1,0\}$（即 $2^1$ 或 $2^0$），细化局部指数。
- **Level 3 `E1_16`**：16 个 1-bit 微指数，每组 4 元素一个。最细粒度。
- **元素 `S1P2`（=E1M2）**：4-bit，1 符号 + 1 整数 + 2 小数，3 位有效数字，表示 $\pm\{0.25, 0.5, ..., 1.75\}$。

> [!note] 为什么 HiF4 用 S1P2 而非 E2M1
> 论文核心论点：**E1M2（S1P2）有 3 位有效数字，比 E2M1 的 2 位精度上限更高**。4-bit 这么窄，每多位有效数字都是质的提升。E2M1 牺牲有效数字换 2-bit 微指数扩大组内动态范围是 NVFP4 的取舍；HiF4 保留 S1P2 的 3 位精度，改用**大组 64 + 两级共享微指数**（开销仅 0.5 bit/value）来补组内动态范围，一举两得——既保精度又压元数据。

**第 $i$ 个元素的真实值**（论文式 2）：

$$V_i = \text{E6M2}\times 2^{(\text{E1\_8}_{\lceil i/8\rceil}+\text{E1\_16}_{\lceil i/4\rceil})}\times \{\text{S1P2}\}_i$$

组内动态范围：最大正 $2^{(1+1)}\times1.75=7$，最小正 $2^{(0+0)}\times0.25=0.25$ → $\log_2(7/0.25)=$ **4.81 binades**（NVFP4 仅 3.58）。

**为什么硬件更省**（论文 §III-B）：64 长度点积里，Level 2/3 微指数可硬件实现为左移、吸收进 S1P2 元素成 5-bit 整数 S2P2 参与乘法；整个 64→1 的压缩树**纯整数运算**，只在末段用 1 个小浮点乘法器（E6M2×E6M2）+ 1 个大整数乘法器。对比 NVFP4 末段要 4 个小浮点乘法器 + 4 个大整数乘法器 + 浮点累加。**HiF4 增量面积约为 NVFP4 的 1/3、功耗降 ~10%**。

**精度实测**（论文，多 LLM 平均精度损失，越接近 0 越好）：

| 模型集 | NVFP4 直转 | NVFP4+PTS | HiF4 直转 | HiF4+HiGPTQ |
|---|---|---|---|---|
| 4 小模型（含 Mistral-7B） | -40.87（Mistral 直接崩到随机水平） | -1.61 | **-1.12** | **-0.76** |
| 3 小模型（不含 Mistral） | -1.81 | -1.68 | **-1.07** | **-0.74** |

NVFP4 直接 cast 在 Mistral-7B 上**精度崩溃到随机猜测水平**（crash），HiF4 直转稳定不崩——这是 HiF4 全局 69 binades 动态范围的直接收益。配合论文改造的 **HiGPTQ**（基于 GPTQ 适配 HiF4 细粒度结构），Qwen2.5-14B 上甚至**超过 BF16 基线**。

## 4. 数学原理 / 公式

### 4.1 BFP 通用表示

一个 BFP 块（$K$ 个元素）的真实值：

$$V_i = \text{Scale}\times \text{MicroScale}_i \times \text{Element}_i, \quad i \in [1, K]$$

- $\text{Scale}$：块共享缩放因子（1 个或层级）。
- $\text{MicroScale}_i$：可选的层级微缩放（HiF4 有两级）。
- $\text{Element}_i$：低 bit 浮点编码值。

### 4.2 量化误差：MSE 比例（论文 §III-A）

对 18 个高斯分布矩阵（$\sigma=0.01\times2^x, x\in[0,17]$）转 4-bit BFP，相对 HiF4 的归一化 MSE：

$$\text{HiF4} : \text{NVFP4} : \text{MXFP4} = 1 : 1.32 : 1.89$$

即 HiF4 量化误差最低，比 NVFP4 低 24%、比 MXFP4 低 47%。NVFP4 在数值接近其表达边界时 overflow/underflow 误差剧增（需 PTS 消除），HiF4/MXFP4 不需 PTS 故无此波动。

### 4.3 HiF4 三级层级缩放的数学（关键公式）

第 $i$ 个元素值（$i\in[1,64]$）：

$$\boxed{V_i = \text{E6M2}\times 2^{(\text{E1\_8}_{\lceil i/8\rceil}+\text{E1\_16}_{\lceil i/4\rceil})}\times \{\text{S1P2}\}_i}$$

- $\text{E6M2}\in\{2^e\times1.M\}$，$e\in[-48,15]$（bias 48），全局组间 scale。
- $\text{E1\_8}_j\in\{0,1\}$（$j\in[1,8]$），每管 8 元素，$2^{\text{E1\_8}}\in\{1,2\}$。
- $\text{E1\_16}_k\in\{0,1\}$（$k\in[1,16]$），每管 4 元素，$2^{\text{E1\_16}}\in\{1,2\}$。
- $\{\text{S1P2}\}_i\in\pm\{0,0.25,0.5,...,1.75\}$，元素本体。

**动态范围**：
- 全局（E6M2 一级）：$[-50,18]$ = **69 binades**（NVFP4 的 E4M3 scale 仅 22）。
- 组内（微指数+E6M2 局部）：最大 $2^{1+1}\times1.75=7$、最小 $2^{0+0}\times0.25=0.25$ → $\log_2(7/0.25)=$ **4.81 binades**（NVFP4 的 E2M1 仅 3.58）。

### 4.4 HiF4 转换算法（BF16 → HiF4，论文 Algorithm 1）

三阶段树形 reduction，把 64 个 BF16 编码成一个 HiF4 单元：

**Stage 1（树形求局部峰值，line 1–7）**：
- Level 1：每 4 元素取 $\max|x|$ → 16 个局部峰值 $V_{16}$。
- Level 2：每 2 个 $V_{16}$ 取 max → 8 个 $V_8$。
- Level 3：8 个 $V_8$ 取 max → 全局峰值 $V_{\max}$。

**Stage 2（推导三级缩放元数据，line 8–14）**：
- 高精度 scale $S_{F}^{BF16} = V_{\max}\times(1/7)$（7 是组内结构最大可表示值）。
- Level 1：$\text{E6M2} = \text{BF16\_to\_E6M2}(S_F)$（专用指令量化成 E6M2）。
- 倒数：$\text{E6M2\_REC} = \text{E6M2\_REC\_to\_BF16}(\text{E6M2})$（4-entry LUT + 指数减法实现）。
- Level 2：$\text{E1\_8} = (V_8\times\text{E6M2\_REC} \geq 4)\;?\;1:0$（8 个并行乘比较）。
- Level 3：$\text{E1\_16}[i] = (V_{16}[i]\times\text{E6M2\_REC}\times2^{-\text{E1\_8}[\lceil i/2\rceil]} \geq 2)\;?\;1:0$（16 个，$2^{-\text{E1}}$ 是 0.5 或 1 可用 bypass 乘法）。

**Stage 3（算组内元素，line 15–18）**：
- $V_{64\_scaled}[i] = V_{64}[i]\times\text{E6M2\_REC}\times2^{-\text{E1\_8}[\lceil i/8\rceil]}\times2^{-\text{E1\_16}[\lceil i/4\rceil]}$
- $\text{S1P2\_64} = \text{BF16\_to\_S1P2}(V_{64\_scaled})$（超出 S1P2 范围则 clamp 到最近边界，保留符号）。

所有舍入用 round-half-to-even 或 round-half-away-from-zero。E6M2 无 subnormal，倒数指令用 4-entry LUT（按 2-bit 尾数索引）+ 简单指数减法即可高效实现。

### 4.5 NVFP4 为什么需要 PTS，HiF4 不需要

- **NVFP4**：scale 用 FP8-E4M3，全局动态范围仅 22 binades。当张量数值分布跨度超过 22 binades（LLM 激活/梯度常见），E4M3 scale 表示不下 → overflow/underflow。**PTS（per-tensor scaling）**：先对整张量乘一个软件算出的粗 scale 把张量峰值压到 E4M3 scale 能覆盖的范围，再量化。多一个软件算子，性能损失，且 scale 在线计算增加 [[训推不一致]] 风险。
- **HiF4**：Level 1 的 E6M2 全局动态范围 69 binades，足以直接覆盖 LLM 张量的数值跨度，**直转即可，不需 PTS**——这是 HiF4 工程上更省心、训推更易一致的根。

### 4.6 64 长度点积计算流（HiF4 vs NVFP4）

矩阵乘基本单元（PE）做 $K=64$ 长度点积时（Tensor Core / Cube Core 都已支持 64 长度 4-bit 点积以翻倍 8-bit 算力）：

$$\text{Dot}(A,B) = \text{E6M2}^A\text{E6M2}^B\sum_{i=1}^{8}2^{(\text{E1\_8}^A[i]+\text{E1\_8}^B[i])}\sum_{j=2i-1}^{2i}2^{(\text{E1\_16}^A[j]+\text{E1\_16}^B[j])}\sum_{k=4j-3}^{4j}(\text{S1P2}^A[k]\times\text{S1P2}^B[k])$$

- **HiF4**：$K=64$ 正好匹配 PE 输入宽度，1 对单元够用。Level 2/3 微指数吸收进 S1P2 成 5-bit 整数 S2P2，压缩树 64→1 **纯整数**，末段 1 个小浮点乘（E6M2×E6M2）+ 1 个大整数乘。
- **NVFP4**：$K=16$，64 长度点积要 **4 对** NVFP4 单元。末段 4 个小浮点乘（E4M3 scale）+ 4 个大整数乘 + 浮点累加树。比 HiF4 多 6 个乘法器，面积 ~3×、功耗 +10%。

### 5.2 手写 BFP 直觉：per-tensor vs per-block 的精度差

```python
import numpy as np

def fp8_e4m3_quantize(x, scale):
    """简化 E4M3：除 scale, clip [-448,448], 取整."""
    q = np.clip(x / scale, -448, 448)
    return np.round(q) * scale          # 反量化回来看误差

x = np.array([0.001, 0.002, 50.0, 100.0])     # 2 个离群点 + 2 个小数

# per-tensor: 一个 scale = 448 / max|x| → 小数被压成 0
s_pt = 448 / np.abs(x).max()                   # 4.48
q_pt = fp8_e4m3_quantize(x, s_pt)
print("per-tensor:", q_pt)                     # [0, 0, 50, 100]  小数 100% 误差

# per-block (K=2): 各块自己 scale → 小数保得住
for i in range(0, len(x), 2):
    blk = x[i:i+2]
    s_blk = 448 / np.abs(blk).max()
    print(f"block{i}:", fp8_e4m3_quantize(blk, s_blk))
# block0: [0.001 0.002] 保住; block1: [50 100] 保住 —— 这就是 BFP 的全部价值
```

  - [[训推不一致]]（BFP 格式统一是消除"精度路径 TIM"的希望——训推都用 MXFP8/HiF4 同规范即可消掉这层差异；NVFP4 的 PTS 反而新增 TIM 风险）。

  - **MXFP8 vs NVFP4 vs HiF4**：见 §3.4 总表——8-bit 甜点 / 4-bit 浮点 scale / 4-bit 层级 scale 三条路线。
  - **块缩放格式 vs 块缩放策略**：BFP 是格式（绑定具体位布局），per-block 是策略（粒度，可不绑格式）；[[FP8量化方案]] §3.2 的 per-block 行指策略，本篇指格式。

## 7. 常见误区与易错点

> [!warning] 误区 1："4-bit 一定比 8-bit 省 2 倍显存就更好"
> 不一定。4-bit 动态范围窄，**权重+激活同时量化容易崩**（NVFP4 直转在 Mistral-7B 上精度崩到随机水平，见 §3.7 实测）。实际常常只能 weight-only，4-bit 算力白浪费——只省显存不省算力。是否划算看具体格式（HiF4 能 W4A4，NVFP4 多 W4-only）。

> [!warning] 误区 2："块越小越准"
> 方向对但有代价。块越小元数据越多，存储/算力开销越大（更早的 MX4 因 $K=16$ 元数据 1 bit/value 被迫组内降到 3 bit 反比 vanilla 差，被 AMD 弃用）。HiF4 设计亮点恰是**组大到 64 + 两级共享微指数**把元数据压到 0.5 bit/value 仍覆盖组内 4.81 binades。块大小是精度-元数据的权衡轴，非越小越好。

> [!warning] 误区 3："NVFP4 和 MXFP4 是一回事"
> 不是。NVFP4 用 FP8-E4M3 **浮点 scale**（充分利用 E2M1 空间但需软件 PTS、硬件面积大），MXFP4 用共享 8-bit **指数 scale**（更省硬件但精度差、多 weight-only），HiF4 用**三级层级 scale**（折中胜出）。三者元素编码、组大小、scale 类型都不同。

> [!warning] 误区 4："MXFP8 是万能省显存"
> 仍需配 per-block E8M0 scale，硬件不支持（SM < 10.0，如 A100/Hopper）跑不动真加速，退化成仿真。Hopper (SM 9.0) 只有 per-tensor FP8，没有 MXFP8 块缩放硬件。

> [!warning] 误区 5：以为块缩放改变"累加必须回 fp32"的规则
> 不变。§[[数值类型与精度]] 8.3 的规则在块缩放下依然成立——块内低精度算 matmul，reduction/累加（softmax 分母、layernorm 均方差、loss 求和、梯度 all-reduce）仍要回 fp32。块缩放只把前向 matmul 的精度提了一档，不改变关键累加的高精度要求。

> [!warning] 误区 6：以为 HiF4 是 NVIDIA 格式
> HiF4 是华为（海思）2026-02 提出（arXiv:2602.11287），原生加速在 Ascend NPU。NVIDIA 侧可通过 GCC（全球计算联盟，github.com/global-computing-consortium/HiFloat4）的库做伪量化仿真测精度，但 Blackwell Tensor Core 不原生加速 HiF4——Blackwell 原生加速的是 NVFP4（自家专有）和 MXFP8（OCP 标准）。跨硬件部署要认清格式归属。

> [!warning] 误区 7：把 PTS 和 per-tensor 量化混为一谈
> PTS（per-tensor scaling）是 NVFP4 **额外**的软件预处理（先粗归一再量化进 E4M3 scale 的窄范围），是补救 E4M3 scale 动态范围不足的手段；per-tensor 量化指 scale 粒度是整张量（per-tensor）。两者都涉及"per-tensor"但层次不同：PTS 是 NVFP4 内部的预处理步骤，per-tensor 是 [[FP8量化方案]] §3.2 的缩放粒度分类。

## 8. 延伸细节

### 8.1 精度栈定位：BFP 在哪一层

精度栈从高到低：**FP32 master → BF16 计算 → FP8/FP4 BFP 块缩放量化**。BFP 不是替代 BF16，而是在 BF16 计算路径的**特定张量**（权重/激活/梯度/KV）上再压一档。master 权重始终 FP32，BFP 不碰 master。所以"4-bit 训练"本质是"BF16 AMP + 选择性 BFP 量化"，不是纯 4-bit 训练。详见 [[FP8量化方案]] §8.4。

### 8.2 HiF4 的训练潜力

论文 §V 提未来工作展开 HiF4 训练。后续工作（arXiv 2026）已把 HiF4 用于：
- **LLM 预训练**（Ascend NPU，Llama3-8B / Qwen3-MoE-30B，约 90% 存储/GEMM 跑 FP4，精度与 BF16 竞争）。
- **RL post-training**（配合 Rollout Residual Quantization / Rollout-ResQ，端到端 FP4 精度做 RL，缩小 ultra-low-bit 与高精度的 gap）。
- **扩散模型**（DiT 类，4-bit 加速）。

### 8.3 与 [[Flash Attention]] 的 online softmax 同构

BFP 的"块共享 scale + 块内低精度"思想，和 Flash Attention 的"分块（tiling）+ online softmax 单遍累加"在**流式分块处理**上是同构的——都是把大张量/大计算切成小块逐块处理、用 running 状态增量更新。Flash Attention 切的是计算（attention 矩阵），BFP 切的是存储（数值量化），但"分块 + 增量"的工程哲学一致。

### 8.4 格式标准化与生态（2026 现状）

- **OCP MX 规范**（v1.3）：开放，MXFP8/MXFP4/MXINT8，NVIDIA/AMD/华为/微软/Meta 共推，是跨厂商统一的最大希望。
- **NVIDIA NVFP4**：专有，Blackwell 独占，吞吐最高但绑死 NVIDIA 硬件 + 需 PTS。
- **华为 HiF4**：主推 Ascend 生态，精度/硬件效率 SOTA，GCC 出了跨平台（CUDA+Ascend）模拟库但无 NVIDIA 原生加速。
- **AMD**：MI350X 支持 MXFP8；Versal 系列弃 MX4 留 MX6/MX9。
- **现状（2026-08）**：8-bit MXFP8 已多厂商落地是甜点；4-bit 仍在普及早期，NVFP4 进 Blackwell 但精度受限（多 weight-only/PTS），HiF4 精度/硬件优但生态偏 Ascend。

### 8.5 选择速查

| 场景 | 推荐格式 |
|---|---|
| Hopper (H100) 训练 | per-tensor FP8（TE delayed scaling，见 [[FP8量化方案]]） |
| Blackwell (B200) 训练/推理 | **MXFP8**（block scaling，精度近无损） |
| Blackwell 极致显存/吞吐（高 batch compute-bound） | NVFP4（配 PTS） |
| Ascend NPU 推理/预训练 | **HiF4**（精度/硬件 SOTA，直转不需 PTS） |
| 跨厂商训推统一 | MXFP8（OCP 开放标准） |
| 老硬件（A100，无 FP8 单元） | 留 BF16 或 INT8 |
