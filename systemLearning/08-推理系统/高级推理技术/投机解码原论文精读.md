## 1. 一句话定义

这是**投机解码（speculative decoding）的两篇奠基原论文**——Google 的 Leviathan, Kalman, Matias（ICML 2023，《Fast Inference from Transformers via Speculative Decoding》）与 DeepMind 的 Chen, Likhomanov, Wooders 等（2023，《Accelerating Large Language Model Decoding with Speculative Sampling》）在 2022 年底/2023 年初**独立、几乎同时**提出同一思想：用一个**小模型（draft/approximation model）串行猜若干 token**，再用**大模型（target）一次 forward 并行验证**，通过**接受-拒绝采样**保证最终输出分布**严格等于**纯大模型采样，从而**无损加速**自回归解码 2–3×。两篇的核心数学（speculative sampling）等价，只是表述与拒绝规则形式不同。

> [!note] 与本库 [[speculative decoding]] 概念笔记的分工
> [[speculative decoding]] 是**概念知识笔记**（以 2026 生产默认的 EAGLE-3 为主线讲清投机解码全貌）。本笔记是**论文精读**，回到 2023 两篇原论文本身：讲它们的**历史背景、CPU 投机执行的类比、算法伪码、无损证明、理论加速上界、实验结果与奠基意义**——即"这个领域从哪开始的"。数学证明的完整版见 [[speculative decoding]] §4，此处给论文视角的推导脉络。


## 2. 为什么需要它（动机与背景）

### 2.1 自回归解码的根本瓶颈：memory-bandwidth bound

大自回归模型（Transformer）解码慢的本质：**每生成 1 个 token 要串行跑 1 次完整 forward，而每次 forward 要把整个模型权重从显存读一遍**。decode 阶段每 token 的算术量很小（相对 prefill），瓶颈在**显存带宽**而非算力——所以单请求解码速度 ≈ 显存带宽 / 模型大小。

> 例：Qwen3-8B FP16 ≈ 16 GB 权重；H100 SXM 带宽 3.35 TB/s，实际 kernel 到 ~75-80%，单 forward ≈ 6–6.5 ms → 单请求解码上限 ≈ 160 tok/s。模型再大也不太变（MoE 只读激活专家的权重）。

**batching 能提吞吐但不能降单请求延迟**——一条 8000 token 的 reasoning trace 仍要 8000 次串行 forward，与 batch 里有无别的请求无关。而 RL rollout 的 step 必须等最慢那条跑完。

### 2.2 论文的关键观察

两篇原论文都基于两个观察：

1. **"难任务含易子任务"**：硬语言建模任务里常含可被更高效模型近似好的容易步骤——不是每步都需要大模型的全部能力。
2. **"大模型推理常不是算力 bound 而是带宽/通信 bound，所以额外算力是空闲可用的"**——大模型 forward 一个 token 与 forward 一批 token 都要读一遍权重，**算力成本相近**。所以可以**用空闲算力并行验证**多个候选，把"每步 1 token"变成"每轮若干 token"。

### 2.3 从 CPU 投机执行借来的类比

Leviathan 论文显式类比 **CPU 的投机执行（speculative execution）**——处理器里"在验证是否需要之前就并行执行任务"的优化，典型例子是**分支预测**：CPU 猜一个分支先跑，猜对就白赚并行度，猜错就回滚。

> **投机执行要有效，需要一个高效的机制去建议"很可能被需要"的任务。**

论文把投机执行**从确定性推广到随机（stochastic）设置**——任务"以某概率被需要"。应用到自回归解码：小模型采的生成作为大模型的"投机前缀"，大模型并行验证它们。关键创新是 **speculative sampling**——一种采样方法，**最大化投机任务被接受的概率，同时保证输出分布严格等于纯 target 采样**。


## 3. 核心概念详解

### 3.1 两阶段：draft 串行猜 + target 并行验

设 target 模型 $M_p$ 分布 $p(x_t|x_{<t})$，更高效的近似模型 $M_q$ 分布 $q(x_t|x_{<t})$。算法三步：

1. **Draft**：用 $M_q$ 串行生成 $\gamma$ 个候选 token $x_1, \dots, x_\gamma$（小模型快、cache 小）。
2. **Verify**：用 $M_p$ 对序列 $[\text{prefix}, x_1, \dots, x_\gamma]$ 做**一次 forward**，并行得到每个位置的 $p(\cdot|x_{<i})$。验证 $\gamma$ 个位置只需 1 次 forward（而非 $\gamma$ 次），因为验证是"给定前缀看每个位置 target 分布"，与生成不同——**这正是利用了带宽 bound 下的空闲算力**。
3. **Accept-Reject**：从左到右逐个判定 $x_i$：
   - 接受 → 继续验证下一个；
   - 拒绝 → 从修正分布重采样 1 个 token 替代 $x_i$，**丢弃其后所有候选**，终止本轮；
   - 全部接受 → target 在第 $\gamma+1$ 位置采样一个 **bonus token**（白送，因 forward 已算）。

所以**每轮 target forward 至少产出 1 个 token（最坏情况不比朴素慢），最多 $\gamma+1$ 个**。

### 3.2 Leviathan（Google）的拒绝采样形式

接受概率与重采样分布：

$$
A(x) = \min\!\left(1, \frac{p(x)}{q(x)}\right), \qquad r(x) = \frac{\max(0,\, p(x) - q(x))}{\sum_{x'} \max(0,\, p(x') - q(x'))}
$$

- $p(x) \ge q(x)$：**必接受**（target 比 draft 更倾向）；
- $p(x) < q(x)$：以 $p/q$ 概率接受，否则从 $r$（归一化的 $(p-q)_+$，即"target 比 draft 多出的余量"）重采样。

### 3.3 Chen（DeepMind）的等价形式

DeepMind 版用**对数域**的修正规则更工程友好，并直接给出"接受概率 = $\min(1, p/q)$"的随机数判定：抽 $u \sim \text{Uniform}(0,1)$，若 $u < \min(1, p(x)/q(x))$ 接受，否则按 $r$ 重采。两者**数学等价**，产出分布都严格 $= p$。

> DeepMind 论文额外强调：**speculative sampling 不限于语言模型**，任何"用廉价近似采样器加速昂贵采样器"的场景都适用——只要能算两个分布的逐点概率比。这是把它抽象成通用采样技术的原因。

### 3.4 为什么 verify 便宜

verify 阶段对 $\gamma$ 个 token 做 1 次 forward，与对 1 个 token 做 1 次 forward **读权重的次数相同**（都读一遍）——decode 是 memory-bound，算力是空闲的。所以验证 $\gamma$ 个候选的边际成本 ≈ 验证 1 个。设 draft 提 4 个、target 接受 3 个 → 得 4 个 token（3 接受 + 1 替换）≈ 1 次普通解码的成本。


## 4. 数学原理 / 公式

### 4.1 无损性证明（论文的核心理论贡献）

要证：最终每个 token 的边缘分布 $\pi(x) = p(x)$。考虑本轮产出的第一个 token：

$$
P(\text{产出 } x) = \underbrace{q(x) \cdot \min\!\left(1, \frac{p(x)}{q(x)}\right)}_{\text{draft 提 x 且被接受}} + \underbrace{(1-\alpha) \cdot \frac{(p(x)-q(x))_+}{1-\alpha}}_{\text{拒绝后从 r 重采样得 x}}
$$

其中 $\alpha = \sum_y \min(p(y), q(y))$，且 $\sum_y (p(y)-q(y))_+ = 1 - \alpha$（因 $\sum p = \sum q = 1$，正部分之和 = 负部分绝对值之和）。代入：

$$
P(\text{产出 } x) = \min(q, p) + (p - q)_+
$$

分情况：
- $p(x) \ge q(x)$：$\min = q$, $(p-q)_+ = p-q$ → 和 $= p$。✓
- $p(x) < q(x)$：$\min = p$, $(p-q)_+ = 0$ → 和 $= p$。✓

两情况都 $= p(x)$。故 $\pi(x) = p(x)$，**严格无损**。后续位置同理（条件分布对齐）。

> [!tip] 关键洞见
> 这不是"近似无损"，是**数学上严格无损**——同一 prompt 用 speculative 与纯 target 采样，得到的序列分布完全相同（仅随机数不同）。这是 speculative decoding 能安全用于 RL 的根（[[verl-SpeCo]] §2.4 据此说"训 drafter 不 bias RL"）。完整推导见 [[speculative decoding]] §4.3。

### 4.2 接受概率 = 1 - TV

单位置期望接受概率：

$$
\alpha = \mathbb{E}_{x \sim q}\!\left[\min\!\left(1, \frac{p(x)}{q(x)}\right)\right] = \sum_x \min(p(x), q(x)) = 1 - \text{TV}(p, q)
$$

其中 $\text{TV}(p,q) = \tfrac{1}{2}\|p - q\|_1$ 是总变差距离。**draft 与 target 分布越接近，接受率越高**——这正是后世 EAGLE 让 draft 学 target 内部 feature 轨迹（而非离散 token）的数学根因，也是 [[verl-SpeCo]] 用 L1 距离直接训 acceptance 的依据。

### 4.3 理论加速上界

设每步接受概率 $\alpha$（独立近似），draft $\gamma$ 个 token，每次 verify pass 产出（含 bonus）：

$$
\tau = \frac{1 - \alpha^{\gamma+1}}{1 - \alpha}
$$

$\alpha \to 1$ 时 $\tau \to \gamma + 1$（全接受 + bonus）。考虑 draft 自身成本 $\beta$（draft 一块 = $\beta$ 个 target pass），净加速：

$$
S = \frac{\tau}{1 + \beta}
$$

> 论文给的最优 $\gamma$ 选择：当 $\alpha$ 高时增大 $\gamma$ 有益；$\alpha$ 低时 $\gamma$ 大反而白花 draft 开销。Leviathan §3.5 给了选 $\gamma$ 使期望墙钟时间最小的解析。

### 4.4 Chen（DeepMind）给的渐进视角

DeepMind 版强调：**speculative sampling 把串行解码的 $\gamma$ 步压缩成 1 步 target forward + $\gamma$ 步廉价 draft**。当 draft 极廉价（$\beta \to 0$）且 $\alpha$ 高时，渐进加速 → $\gamma+1$。这与 Google 版结论一致，只是 framing 从"接受-拒绝"换成"采样成本分解"。


## 5. 代码示例（论文算法的最小复现）

Leviathan Algorithm 1 的核心逻辑（贪心/sampling 通用，此处用 sampling）：

```python
import torch
import torch.nn.functional as F

def speculative_decode(target, draft, prompt_ids, k=4, max_new=30, temperature=1.0):
    """两篇原论文的投机解码最小复现。
    target/draft: 能返回 logits 的模型（draft 更轻量）。
    保证：输出分布 == 纯 target 采样（仅随机数不同）。
    """
    ids = prompt_ids.clone()
    for _ in range(max_new):
        # Stage 1: draft 串行猜 k 个
        draft_tokens, draft_probs = [], []
        cur = ids
        for _ in range(k):
            with torch.no_grad():
                q_logits = draft(cur)[:, -1, :] / temperature
            q_probs = F.softmax(q_logits, dim=-1)
            x = torch.multinomial(q_probs, num_samples=1)   # x ~ q
            draft_tokens.append(x)
            draft_probs.append(q_probs)
            cur = torch.cat([cur, x], dim=-1)

        draft_tokens = torch.cat(draft_tokens, dim=-1)       # [1, k]
        draft_probs = torch.cat(draft_probs, dim=0)          # [k, V]

        # Stage 2: target 一次 forward 并行验证 k+1 个位置
        with torch.no_grad():
            p_logits = target(torch.cat([ids, draft_tokens], dim=-1))[:, -k-1:, :] / temperature
        p_probs = F.softmax(p_logits, dim=-1)                # [k+1, V]

        # Stage 3: 接受-拒绝
        n_accept = 0
        for i in range(k):
            x_i = draft_tokens[:, i]
            p_xi = p_probs[i].gather(-1, x_i)
            q_xi = draft_probs[i].gather(-1, x_i)
            # 接受概率 min(1, p/q)
            if torch.rand(1).item() < min(1.0, (p_xi / q_xi).item()):
                ids = torch.cat([ids, x_i], dim=-1)
                n_accept += 1
            else:
                # 拒绝：从 (p - q)+ 归一化重采样 1 个，终止本轮
                residual = (p_probs[i] - draft_probs[i]).clamp(min=0)
                residual = residual / residual.sum()
                x_new = torch.multinomial(residual, num_samples=1)
                ids = torch.cat([ids, x_new], dim=-1)
                break
        else:
            # 全接受：bonus token（target 已算第 k+1 位置）
            bonus = torch.multinomial(p_probs[-1], num_samples=1)
            ids = torch.cat([ids, bonus], dim=-1)

        if ids.size(-1) - prompt_ids.size(-1) >= max_new:
            break
    return ids[:, prompt_ids.size(-1):]

# 注：以上为教学复现，生产用 vLLM/SGLang 的 spec decode 实现（tree attention、
# cuda graph、kv cache 管理远比此处复杂）。见 [[speculative decoding]] §5。
```


## 6. 与其他知识点的关系

- **上游（依赖）**:
  - [[autoregressive decoding]]（投机解码加速的对象；自回归串行是它要攻的瓶颈）
  - [[采样策略]]（speculative 是采样加速的一种；与贪心/sampling/beam 的关系）
  - [[GPU utilization]]（decode 的 memory-bound 是 speculative 收益的物理根）
- **下游（应用）**:
  - [[speculative decoding]]（概念笔记，EAGLE-3 为主线讲清全貌与演进）
  - [[verl-SpeCo]]（把原论文的静态 draft 推广到 RL 循环内协同训练）
  - [[parallel decoding]]（Medusa/Lookahead 等无独立 draft 的变体，受原论文启发）
- **对比 / 易混**:
  - **Leviathan(Google) vs Chen(DeepMind)**：同年独立工作，算法等价；Google 版用 rejection sampling 框架表述，DeepMind 版用对数域修正 + 通用采样器视角。业界引用 Leviathan 更多（ICML 正会、T5-XXL 实测）。
  - **vs 蒸馏**：蒸馏让小模型永久替换大模型（改分布）；speculative 让小模型辅助大模型加速，大模型仍是最终裁判（分布不变）。
  - **vs [[beam search]]**：beam 是搜索（改分布，追求高概率输出）；speculative 是采样加速（保分布，不改变质量）。两者正交。
  - **vs 自适应计算**（early-exit/层跳）：自适应计算改模型结构/训练；speculative 不改模型、不重训、不改分布，即开即用——这是论文强调的"off-the-shelf"优势。


## 7. 常见误区与易错点

> [!warning] 误区 1：以为 speculative 是"近似无损"
> 论文证明的是**严格无损**（§4.1）——输出分布数学上等于 target 分布。不是"差不多无损"。"近似无损"会让人怀疑能否用于 RL/评估，而严格无损意味着用它生成的样本分布与纯 target 完全一致（仅随机数不同）。

> [!warning] 误区 2：以为加速来自"小模型算得快"
> 加速的**主因不是 draft 快，而是 verify 便宜**——target 一次 forward 验证 $\gamma$ 个候选 ≈ 验证 1 个的成本（因 decode memory-bound，算力空闲）。draft 快只是前提（draft 不能比 verify 还慢）。draft 太弱（$\alpha$ 低）每轮接受 0–1 个，draft 开销纯浪费，可能负优化。

> [!warning] 误区 3：以为两篇是同一团队
> 是 Google（Leviathan/Kalman/Matias，ICML 2023）与 DeepMind（Chen 等，2023）**独立同时**提出。arXiv 上 Google 版 2022-11-30、DeepMind 版 2023-02-02。算法等价但表述不同，引用时勿混作者归属。

> [!warning] 误区 4：忽略"最坏情况不比朴素慢"的保证
> 论文保证**每次 target forward 至少产出 1 个 token**（最坏情况 = 全拒绝 → 1 个 target 自采 token）。所以 speculative 的最坏墙钟时间 ≤ 朴素自回归——这是它能被默认开启的安全网。但加上 draft 开销后，最坏总时间可能略超（draft 白跑了）。

> [!warning] 误区 5：把 $\gamma$ 调得越大越好
> $\tau = (1-\alpha^{\gamma+1})/(1-\alpha)$ 有上界 $1/(1-\alpha)$。$\alpha$ 低时增大 $\gamma$ 收益递减还白增 draft 成本。论文 §3.5 给了选最优 $\gamma$ 的方法——$\gamma$ 要匹配 $\alpha$ 与 draft/target 速度比。


## 8. 延伸细节

### 8.1 论文实验结果

| 论文 | 模型 | 任务 | 加速 |
|---|---|---|---|
| Leviathan (Google) | T5-XXL (11B) + T5-small draft | 翻译/摘要 | **2–3×**（vs T5X 实现，输出完全一致） |
| Leviathan | LaMDA (137B) | 对话 | 显著加速（论文 Fig.5） |
| Leviathan | 97M GPT-like + 6M draft | lm1b 无条件生成 | 38 token 句子仅需 9 次 target 串行 forward |
| Chen (DeepMind) | — | 通用采样器加速 | 等价加速，强调框架普适 |

> 两篇都强调：**无需重训、无需改架构、输出不变**，"off-the-shelf"即可加速已发布模型——这是它迅速被工业界采纳的原因。

### 8.2 为什么是奠基（领域影响）

这两篇定义了"speculative decoding"这个名字与范式，催生了整个研究方向：

1. **算法层**：后续 EAGLE-1/2/3（改 draft 预测 feature 而非 token，接受率 50%→80%）、Medusa（并行头）、Lookahead/Jacobi（无 draft）等都是在这套"draft + verify + accept-reject"骨架上演进 draft 来源与验证结构。
2. **理论层**：无损证明（§4.1）是所有后续工作"安全性"的基石——只要保持 accept-reject 框架，加速不改变分布。这也是 [[verl-SpeCo]] 敢在 RL 循环内训 drafter 的数学根。
3. **系统层**：vLLM/SGLang/TensorRT-LLM 都把 spec decode 作为一等公民支持（见 [[speculative decoding]] §8.2 引擎支持表）。
4. **RL 层**：2026 年 [[verl-SpeCo]]、slime/Miles、SpecForge 把 drafter 训练搬进 RL 循环，正是为解决原论文"draft 绑定固定 target"在 RL 中失效的问题。

### 8.3 论文留下的开放问题（被后续工作接续）

| 原论文的局限 | 后续解决 |
|---|---|
| 需独立同族小 draft model（70B 配 8B） | EAGLE 系：target 上挂轻量 head，无第二完整模型 |
| draft 预测离散 token，对齐难，$\alpha$ ~0.5 | EAGLE-1：改预测 hidden feature，$\alpha$ 0.7–0.8 |
| 静态 draft 绑定单一 target | [[verl-SpeCo]]：RL 循环内协同训练 |
| 线性猜 $\gamma$ 个，单链验证 | EAGLE-2：动态 draft tree + tree attention 一次验多分支 |
| draft 的 lm_head 是大词表瓶颈 | NanoSpec：动态词表裁剪 40× |
